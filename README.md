# Calm Hustle Co. - Backend API

Laravel REST API for the Calm Hustle Co. product catalog. It provides registration, login, logout (Laravel Sanctum bearer tokens) and role-based Product CRUD.

## Prerequisites

- PHP 8.2 or newer
- Composer
- Git

## Installation

```bash
git clone https://github.com/kokekoks/calm-hustle-backend.git
cd calm-hustle-backend
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan db:seed --class=AdminSeeder
php artisan serve
```

On Windows PowerShell, use `copy .env.example .env` instead of `cp`.

The API runs at `http://localhost:8000/api`.

## Environment variables

Copy `.env.example` to `.env`. Never commit `.env`. Values to set locally:

| Variable | Purpose |
|---|---|
| `APP_KEY` | Generated by `php artisan key:generate` |
| `DB_CONNECTION` | Database driver (SQLite by default) |
| `ADMIN_EMAIL` | Email of the seeded administrator |
| `ADMIN_PASSWORD` | Password of the seeded administrator (choose your own) |

## Authentication endpoints

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/api/register` | No | Create a customer account (`first_name`, `last_name`, `email`, `password`, `password_confirmation`) |
| POST | `/api/login` | No | Returns `access_token` and safe user fields |
| POST | `/api/logout` | Bearer token | Revokes the current token |

Send the token with every protected request:

```
Authorization: Bearer <access_token>
Accept: application/json
```

## Product and category endpoints

| Method | Endpoint | Who may access |
|---|---|---|
| GET | `/api/products` | Any authenticated user |
| GET | `/api/products/{id}` | Any authenticated user |
| POST | `/api/products` | Admin only |
| PUT / PATCH | `/api/products/{id}` | Admin only |
| DELETE | `/api/products/{id}` | Admin only |
| GET | `/api/categories`, `/api/categories/{id}` | Any authenticated user |
| POST | `/api/categories` | Admin only |
| GET / POST / PUT / DELETE | `/api/users` | Admin only |

## Roles and permissions

| Requester | Result |
|---|---|
| Guest (no token) | `401 Unauthenticated` on every protected endpoint |
| Authenticated customer | May list and view products; create, update and delete return `403 Forbidden` |
| Administrator | May list, view, create, update and delete products |

- Public registration always creates a `customer`. The `role` field is ignored, so nobody can register as an administrator.
- The administrator is created by `AdminSeeder` using `ADMIN_EMAIL` and `ADMIN_PASSWORD` from `.env`.
- Authorization is enforced on the server by `App\Http\Middleware\AdminMiddleware`.

## Test accounts

- Administrator: the email and password you set in `.env` before running the seeder.
- Customer: register one through `POST /api/register` or the frontend Register page.

No real passwords are stored in this repository.

## Differences from the example API contract

- The user primary key is `user_id`, the product primary key is `product_id`, and the quantity field is `stock`.
- A product has a `category_id` and the response includes a `category` object with `category_name`.
- Collections and single resources are wrapped in a `data` property.
- Registration returns the new user without a token. The user then logs in.
- Product update accepts both `PUT` and `PATCH`.

## Known limitations

- Tokens do not expire automatically; they are revoked on logout.
- Product images are stored as image URLs, not uploaded files.
